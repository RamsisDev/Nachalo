# Changelog

## Unreleased

The wire format, `CI` and the test vectors are unchanged; `PROTOCOL` stays `"Nachalo v0"`.

- **Receivers accept payloads up to `PAYLOAD_CEILING` (8192 bytes)**, whatever they send
  themselves. An implementation that still rejects payloads over 1024 bytes fails against one
  that sends more.
- **Local, configurable limits.** `INVITE_TTL`, `MAX_ANSWERS`, `MAX_PAYLOAD` and
  `APPOINTMENT_WINDOW` are no longer constants: each device picks `invite_ttl`, `max_answers`,
  `max_payload` and `appointment_window` through a `Config`, from the profiles `INTERACTIVE` (the
  previous values, and the default), `PQ_MESSENGER` and `NEARBY`, within each profile's ranges.
- **The wall clock is checked at every step.** An appointment or physical-token invitation kept
  in memory used to complete a handshake after its window closed or its token expired. Every step
  now takes a `Clock` (`now` and `now_unix`) and returns `Expired` outside the window.
- **The responder's answer cap is enforced** by `Listener`, which replaces `Responder::respond`.
- `new_physical_token` returns a `Result` and rejects an expiry that overflows. `Error` is
  `#[non_exhaustive]` and gains `OutOfRange`.
- **Pending steps can be saved.** `Initiator`, `Responder` and `Listener` gain `to_bytes` and
  `from_bytes`, so a handshake survives the OS killing the app. The state starts with a version
  byte and holds secrets: store it encrypted. `Listener` now keeps its own copy of the invitation
  and has no lifetime parameter.
- **Each step's TTL also runs on the wall clock**, so a step restored after a restart, which
  resets the monotonic clock, still expires on time.
- **A failing OS random generator is an error, not a panic**: `words` returns a `Result`, and
  `Error` gains `Rng`.
- **Words are looked up in constant time**, by index into the list and, when typed, compared with
  every list word.
- **The published crate includes `vectors/` and `docs/`**, so `cargo test` passes on the crates.io
  download.
- **Negative test vectors**, `vectors/v0-negative.json`: messages and times that must be rejected.
- Fuzz targets (`fuzz/`), property tests and benchmarks. Every public item is documented.
- **Bindings for TypeScript, Kotlin, Swift and Go.** The repository is a Cargo workspace with two
  new crates over the unchanged core: `nachalo-wasm` (wasm-bindgen, for Node.js and browsers) and
  `nachalo-uniffi` (UniFFI 0.31.0, for Kotlin and Swift, and for the Go package in `bindings/go`,
  generated by uniffi-bindgen-go v0.7.1+v0.31.0). They need `Listener`'s own copy of the
  invitation, above, to keep it inside a foreign object.
- **A symbolic model in ProVerif**, `formal/`, of the handshake in each invitation mode: no
  offline test of the words, secret keys and payloads, mutual authentication, safety words that
  catch a man in the middle who knows the words, and keys that ML-KEM-768 alone keeps secret from
  a future quantum computer. `formal/check.sh` runs it, and so does CI when a release is
  published. It also shows that B's payload, sealed before B knows who sent msg1, is protected
  only by CPace against that quantum attacker.
