# Nachalo for Go

Package `github.com/RamsisDev/Nachalo/bindings/go/nachalo`, generated by
[uniffi-bindgen-go](https://github.com/NordSecurity/uniffi-bindgen-go) v0.7.1+v0.31.0 from
[`nachalo-uniffi`](../uniffi/README.md), the same library the Kotlin and Swift bindings use. Each
function converts types and calls the Rust core; the core's documentation holds for every
function here.

## Requirements

The package calls the Rust library through cgo. **It needs `CGO_ENABLED=1` and a C toolchain**
(gcc or clang) for the target, plus the Rust library built for that same target: there is no
pure-Go build and no cross-compiling with `GOOS`/`GOARCH` alone.

## Build

Build the static library, so the Go binary carries it and needs no `.so` or `.dylib` at run time,
and point cgo at it:

```bash
cargo build -p nachalo-uniffi --lib --release
cargo rustc -p nachalo-uniffi --lib --release --crate-type staticlib -- --print native-static-libs
export CGO_ENABLED=1
export CGO_LDFLAGS="$PWD/target/release/libnachalo_uniffi.a -lgcc_s -lutil -lrt -lpthread -lm -ldl -lc"
go get github.com/RamsisDev/Nachalo/bindings/go
```

Pass the archive by its path, not with `-lnachalo_uniffi`, which picks the shared library when
both are present. The system libraries after it are the ones the second command prints under
`native-static-libs`: the list above is Linux's; on macOS it is shorter. `CGO_CFLAGS` needs
nothing: the header, `nachalo.h`, ships next to the Go code.

Tests, from `bindings/go`, with the variables above: `go vet ./... && go test ./...`. They run a
live handshake, wrong words, a man in the middle, and the appointment and physical-token modes.

## Generated code

`nachalo/nachalo.go` and `nachalo/nachalo.h` are generated and committed, so `go get` works.
After a change to `bindings/uniffi`, regenerate them with `bindings/go/generate.sh`, which needs
uniffi-bindgen-go at the pinned tag and Go on `PATH`:

```bash
cargo install uniffi-bindgen-go --git https://github.com/NordSecurity/uniffi-bindgen-go --tag v0.7.1+v0.31.0 --locked
bindings/go/generate.sh
```

CI fails if the committed code differs from a fresh generation.

## The API

The Rust API, exported in PascalCase: `InvitationLive`, `InvitationAppointment`,
`InvitationPhysicalToken`, `InitiatorStart`, `NewListener`, `NewConfig`, and methods such as
`Finish`, `Respond`, `SafetyWords`, `Verify`, `Confirm`. `InitiatorStart` returns an `*Initiator`
whose `Msg1()` is the first message, `Respond` an `Answer` (`Responder`, `Msg2`), and `Finish` a
`Finished` (`Unconfirmed`, `Msg3`). Times are `uint64`; durations in `Config.With*` are seconds.
The constants are functions: `PayloadCeiling()`, `Msg1Len()`, `Msg2Len(payload)`,
`Msg3Len(payload)`, `RendezvousLen()`, `TokenLen()`, `WordCount()`, `AppointmentWordsA()`,
`AppointmentWordsB()`.

**Errors** are returned as `error`. Match them with `errors.Is` against
`ErrNachaloErrorBadWords`, `ErrNachaloErrorExpired`, `ErrNachaloErrorPayloadTooLarge`,
`ErrNachaloErrorRejected`, `ErrNachaloErrorOutOfRange`, `ErrNachaloErrorRng` and
`ErrNachaloErrorOther` (a failure these bindings do not know yet), or with `errors.As` against
`*NachaloError` or `*NachaloErrorRejected` and the like. `Rejected` never says which check
failed. As in Rust, a failed `Finish` leaves its object usable, and `Initiator.Finish` returns
`Expired` once it has succeeded. `Unconfirmed.Confirm` consumes the object: any later call on it,
`SafetyWords` included, returns `Expired`.

## Secrets

Every object holding secret material (`Invitation`, `Initiator`, `Listener`, `Responder`,
`Unconfirmed`, `Established`, and the `Answer` and `Finished` holding them) wipes it in Rust when
destroyed. Go has no destructors and a finalizer may never run, so **call `Destroy()`** as soon as
a step is done, typically with `defer`.

What crosses into Go is a copy that Rust's zeroizing does not reach: the words, the physical
token, both payloads, `Key()`, `Export()`, and the strings and slices you pass in. Overwrite the
slices you own with `clear()` once done (strings cannot be wiped), and keep them out of logs.

## Example

The live example of [the root README](../../README.md#reference-implementation):

```go
package main

import (
	"bytes"
	"errors"
	"log"

	"github.com/RamsisDev/Nachalo/bindings/go/nachalo"
)

func main() {
	if err := run(); err != nil {
		log.Fatal(err)
	}
}

func run() error {
	context := []byte("my-app v1")                          // equal on both sides, never sent
	config := nachalo.NewConfig(nachalo.ProfileInteractive) // local limits; each side may pick its own
	defer config.Destroy()
	// Each device's monotonic seconds and wall-clock Unix seconds, read before every step.
	clock := nachalo.Clock{Now: 0, NowUnix: 1_900_000_000}

	// A's device draws the words, and A gives them to B; both sides build the invitation.
	words, err := nachalo.Words(nachalo.WordCount())
	if err != nil {
		return err
	}
	invitation, err := nachalo.InvitationLive(words, context, config)
	if err != nil {
		return err
	}
	defer invitation.Destroy()

	// A posts msg1 at invitation.Rendezvous(); B listens there and answers.
	a, err := nachalo.InitiatorStart(invitation, []byte("A's payload"), clock)
	if err != nil {
		return err
	}
	defer a.Destroy()
	listener := nachalo.NewListener(invitation)
	defer listener.Destroy()
	answer, err := listener.Respond(a.Msg1(), []byte("B's payload"), clock)
	if err != nil {
		return err
	}
	defer answer.Destroy()
	finished, err := a.Finish(answer.Msg2, clock)
	if err != nil {
		return err
	}
	defer finished.Destroy()
	unconfirmedB, err := answer.Responder.Finish(finished.Msg3, clock)
	if err != nil {
		return err
	}
	defer unconfirmedB.Destroy()

	// B reads out the safety words, A types them, and B confirms once A says they matched.
	safety, err := unconfirmedB.SafetyWords()
	if err != nil {
		return err
	}
	sessionA, err := finished.Unconfirmed.Verify(safety, clock)
	if err != nil {
		return err
	}
	defer sessionA.Destroy()
	sessionB, err := unconfirmedB.Confirm(clock)
	if err != nil {
		return err
	}
	defer sessionB.Destroy()

	if !bytes.Equal(sessionA.Key(), sessionB.Key()) {
		return errors.New("keys differ")
	}
	return nil
}
```

The other modes only change how the invitation is built: `InvitationAppointment(wordsA, wordsB,
at, context, nowUnix, config)` and `InvitationPhysicalToken(words, token, context, nowUnix,
config)`, with `NewPhysicalToken(lifetime, nowUnix)` making the token.
